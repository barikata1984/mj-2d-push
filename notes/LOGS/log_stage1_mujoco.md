# Stage 1: MuJoCo pusher-slider シミュレーション

## 2026-06-03: 初期実装完了

### 環境構築

- MuJoCo 3.8.1 を pixi 経由で導入
- UR5e モデルは mujoco_menagerie (google-deepmind) から sparse clone
- ffmpeg, Pillow を追加(動画レンダリング用)

### シーン設計 (`stage1_scene.xml`)

- テーブル高さ z=0.3m(z=0 だと UR5e の重力補償が不足し腕がたわむ)
- スライダ: 80x60x30mm, m=1.05kg, condim=4(ねじれ摩擦有効)
- 摩擦パラメータ: µ_pusher=0.3, µ_ground=0.35 (Hogan 2016 Table 1 準拠)
- プッシャ: wrist_3_link の子ボディとして 5mm 球体チップを追加
- 接触ペア明示指定, ロボットアーム各リンクとテーブル/スライダの接触除外

### MPC コントローラ (`pusher_slider_mpc.py`)

- Hogan & Rodriguez 2016 の Family of Modes (FOM) アプローチ
- 3モードスケジュール(M1: 上滑り→固着, M2: 下滑り→固着, M3: 固着のみ)
- 各スケジュールで凸 QP を scipy SLSQP で解き, 最小コストを選択
- 準静的仮定により A=0, 予測は x_k = x_0 + dt * Σ(B_j * u_j)
- 平均 MPC 計算時間: ~6-9ms/ステップ

### ロボット制御

- PD 位置制御アクチュエータに対し, ヤコビアン擬似逆行列経由で ctrl を蓄積
- ctrl += J_pinv @ (v_desired * dt) で重力サグを暗黙補償
- z 方向は比例制御(gain=5)でテーブル面高さを維持

| MPC ステップ数 | 234 |

## 2026-06-03: Stage 0 vs Stage 1 Δθ 突き合わせ実験

### 実験概要

Stage 0 (解析 LS モデル) と Stage 1 (MuJoCo) で同一パラメータの直線プッシュを実施し, Δθ(t) を比較.

- スクリプト: `experiments/exp_dtheta_comparison.py`
- 出力: `results/exp_dtheta_comparison/`

### パラメータ

| 項目 | 値 |
|---|---|
| スライダ寸法 | 80 x 60 mm |
| 質量 | 1.05 kg |
| µ_pusher | 0.3 |
| µ_ground | 0.35 |
| 限界面特性長 c | 0.02887 m (= sqrt((a^2+b^2)/12)) |
| 押し速度 | 0.02 m/s (+y 方向一定) |
| 時間 | 2.0 s |

### 条件

- **A: 中心プッシュ (px=0)**: スライダ -y 面中心に接触
- **B: 偏心プッシュ (px=+20mm)**: -y 面上で +x 方向に 20mm オフセット

### 結果

| 条件 | Stage 0 最終θ | Stage 1 最終θ | 比率 | Pearson r |
|---|---|---|---|---|
| A: 中心 | 0.00° | -0.29° | N/A (解析=0) | N/A |
| B: 偏心 20mm | +27.84° | +19.22° | 0.690 | 0.9975 |

### 考察

1. **条件 A**: 解析モデルは対称性により θ=0 を正確に再現. MuJoCo は -0.29° のドリフトを示すが, これはロボットアームのコンプライアンス, 有限接触剛性, 数値積分誤差に起因.
2. **条件 B**: 両モデルとも単調増加する回転を生成し, 時間的傾向は高い相関 (r=0.998). MuJoCo は解析モデルの約 69% の回転量. 差異の主因は:
   - 解析モデルが完全固着 (sticking) を仮定するのに対し, MuJoCo は接触ソルバで滑りを許容
   - 地面摩擦がトルクとして回転を抑制(解析モデルは準静的で地面摩擦の回転抵抗を無視)
   - 慣性効果(解析モデルは準静的仮定で慣性項なし)
3. y 方向変位は両モデルで良好に一致(2s で約 0.04m, 期待値 0.04m).

## 2026-06-03: CoM オフセット条件 A/B/C 対照実験

### 実験概要

Stage 0 で確認した CoM 信念 → 誘起回転の A/B/C 対照を MuJoCo 上で再現.

- スクリプト: `experiments/exp_com_abc.py`
- 出力: `results/exp_com_abc/`

### 手法

- MuJoCo シーン XML の `<inertial pos>` を動的書き換えし, スライダの CoM を body x 方向に 0–20mm オフセット
- MPC コントローラの target_x を条件別に設定:
  - **A (幾何中心)**: target_x = 0 (CoM オフセット無視)
  - **B (推定 CoM)**: target_x = -est_d (解析推定器で推定したオフセット分だけ目標をずらす)
  - **C (真の CoM)**: target_x = -d (真のオフセット分だけ目標をずらす)
- MPC は全条件で同一モデル(CoM=body 原点を仮定). 差異は目標軌道のみ

### パラメータ

| 項目 | 値 |
|---|---|
| CoM オフセット | 0, 2, 5, 8, 10, 12, 15, 18, 20 mm |
| 押し速度 | 0.04 m/s |
| MPC dt | 0.05 s, horizon = 5 |
| 走行距離 | y: 0.235 → 0.78 |

### 結果

| d (mm) | A: 幾何中心 (deg) | B: 推定 (deg) | C: 真 (deg) |
|---|---|---|---|
| 0 | 0.16 | 0.19 | 0.16 |
| 5 | 4.06 | 3.98 | 3.50 |
| 10 | 15.24 | 12.16 | 12.68 |
| 12 | 18.57 | 16.03 | 16.02 |
| 18 | 32.98 | 28.77 | 28.96 |
| 20 | 39.35 | 35.89 | 35.68 |

### 考察

1. **A > B ≈ C の傾向は確認**. d >= 10mm で A が B/C を上回る. d=20mm で A-B 差は約 3.5°, A-C 差は約 3.7°.
2. **Stage 0 に比べ対照は弱い**. MPC のフィードバックループが回転を部分的に補正するため, Stage 0 の開ループモデルで見られた A ≫ B ≈ C ほどの大きな差は生じない. これは物理的に正しい: 閉ループ制御は CoM 信念誤差の影響を軽減する.
3. **B ≈ C**: 解析推定器の精度が高く(推定誤差 < 0.4mm), B と C はほぼ同一の結果.
4. **d = 8mm で A < B の逆転が 1 点あり**. MPC の非線形応答による局所的なノイズ. 全体傾向としては A > B ≈ C が成立.
5. **回転の主因**: MPC 内部モデルの CoM 仮定(body 原点)と MuJoCo 物理の CoM がずれることで, MPC の回転予測が系統的に誤り, 蓄積回転が発生. target_x 補正は位置誤差を減らすが, 回転ダイナミクスの予測誤差は補正しない.

## 2026-06-03: 圧力分布非一様性の影響検証

- スクリプト: `experiments/exp_pressure_distribution.py`
- 出力: `results/exp_pressure_distribution/`

### 条件

5 種の圧力分布 × 2 制御モード = 10 条件:
- **U**: 均一 (デフォルト)
- **E1**: +x 方向に CoM 15mm シフト
- **E2**: -x 方向に CoM 15mm シフト
- **E3**: +y 方向に CoM 10mm シフト
- **C**: 角部 (+x 15mm, +y 10mm)

制御モード:
- **Aware**: 補正された限界面パラメータ c を使用
- **Unaware**: 均一圧力の c をそのまま使用

### 結果

| ケース | Aware |Δθ| (°) | Unaware |Δθ| (°) | x ドリフト (mm) | 成否 |
|---|---|---|---|---|
| U | 0.06 | 0.06 | 2.0 | 成功 |
| E1 (+x) | 20.8 | 21.3 | 17.1 | 失敗 |
| E2 (-x) | 20.3 | 20.7 | 17.8 | 失敗 |
| E3 (+y) | 0.20 | 0.20 | 1.2 | 成功 |
| C (角) | 8.4 | 10.8 | 16.4 | 失敗 |

### 知見

1. **押し方向と直交する CoM シフト (x 方向) が支配的**: E1/E2 で ~20° の回転が発生しプッシュ失敗
2. **押し方向の CoM シフト (y 方向) は無害**: E3 は均一とほぼ同等
3. **c 補正の効果は限定的**: 角部ケースで aware/unaware 差は 2.4° (22% 改善). x シフト単独では ~0.5° の差のみ
4. c の補正だけでは不十分 — 圧力重心シフトによるトルクをダイナミクスモデルに直接組み込む必要あり

## 2026-06-03: 準静的条件の限界速度調査

- スクリプト: `experiments/exp_speed_limit.py`
- 出力: `results/exp_speed_limit/`

### 速度範囲

7 速度: [0.02, 0.05, 0.08, 0.12, 0.20, 0.35, 0.50] m/s

判定基準: 準静的妥当性比率 = max_accel / (μ_ground × g)
- \> 0.1: 準静的仮定に疑問
- \> 0.5: 準静的仮定が破綻

### 結果

| 速度 (m/s) | x ドリフト (mm) | θ 最終 (°) | 接触損失数 | 準静的比率 | 判定 |
|---|---|---|---|---|---|
| 0.02 | 0.3 | 0.07 | 0 | 0.27 | 疑問 |
| 0.05 | 2.3 | 0.01 | 2 | 0.22 | 疑問 |
| 0.08 | 4.5 | 0.16 | 2 | 0.20 | 疑問 |
| 0.12 | 3.3 | 0.13 | 3 | 0.18 | 疑問 |
| 0.20 | 4.3 | 1.38 | 7 | 0.26 | 疑問 |
| 0.35 | 6.3 | 0.51 | 10 | 1.14 | **破綻** |
| 0.50 | 3.1 | 0.75 | 600 | 1.41 | **破綻** |

### 知見

1. **臨界速度**: ~0.35 m/s で準静的比率が 1.0 を超え, 明確に準静的仮定が破綻
2. **0.02-0.20 m/s**: 全て準静的比率 0.18-0.27 の範囲. 厳密には微妙だが, 制御性能 (x ドリフト, θ 誤差) は良好で実用上問題なし
3. **0.35 m/s 以上**: 接触損失イベントが急増 (10→600), θ 誤差・x ドリフトも増大
4. **0.50 m/s**: 30s のタイムアウトまで y_goal に到達せず (接触維持困難)
5. **実用的な上限**: ~0.20 m/s. これ以下では MPC の制御品質がロバストに維持される

### Fault Tree Debug: spring_link-table 衝突問題

**症状**: グリッパ指先が目標高さ (z=0.315) から +6mm 浮き上がり, スライダと接触不能.

**調査過程** (排除した仮説):
| 仮説 | 排除証拠 |
|---|---|
| Jacobian 列順 | DOF 0-5 = アーム, グリッパ列ノルム = 0 |
| アクチュエータ力飽和 | 全関節で限界値の半分以下 |
| PD ゲイン不足 | 10 倍でも z エラー不変 (5.9mm) |
| 重力補償符号誤り | 符号反転しても改善なし |
| equality constraint | 無効化しても変化なし |

**Root cause**: グリッパ `spring_link` ボディの衝突メッシュ (STL) がテーブル面に接触し, ~100N の法線力がアームを z 方向に押し上げ.

**修正**: `stage1_scene.xml` にグリッパ全リンケージボディの table exclude を追加 → z エラー 6.0mm → 0.2mm.

### シミュレーション結果

修正後, スライダは y=0.78 のゴールに到達:
- 到達時間: ~21.5s
- x ドリフト: 0.18m (右フォロワーの非対称接触による)
- θ 回転: -13°
- z 安定性: ±0.2mm (良好)
- MPC vn: push_speed (0.03 m/s) でフロアクランプ (MPC 自体は最低速度を出力)

### 残課題

- フォロワーメッシュ依存の接触 → パッド面活用またはプッシャジオメトリ追加が必要
- MPC 接触モデルと実接触点の不整合 → vt 制御が効かず横ドリフト未修正

## 2026-06-04: 鉛直 pusher 化 + 作業板 + base フレーム整列

### 診断 (動画で報告された 3 問題)

物体がグリッパ上に乗る / 机にめり込む / y 軸から乖離 の根因は, keyframe が**位置のみ IK** (姿勢無拘束) で tool0 が鉛直から 46° 傾いた横向き解に収束していたこと, および横向きグリッパの非対称接触・グリッパ-机 exclude による視覚的貫通.

### 座標系の整理

- 状態空間モデル (`pusher_slider_mpc.py`) の基準は **world**. robot `base` は元 quat `0 0 0 -1` (z 周り 180°) で base +y = world −y だった.
- ROS UR では `base` (コントローラ基準, 180° 回転) と `base_link` (REP-103) は別フレーム. 本 model には `base` のみ存在.
- 「base 基準」を満たしつつ作業板をテーブル上 (base y [0.35,0.95]) に置くには base +y が押し方向 (world +y) を向く必要 → **base quat を単位に再定義** (`ur5e_with_gripper.xml`). 以後 base = world 整列 (y に +0.1, z に +0.3 のオフセットのみ).

### シーン変更

- 作業板 `work_surface`: base y [0.35,0.95], 半幅 0.325m, 厚さ 27mm, ベージュ材. テーブルを y[0,1.1] に拡張し支持. 赤ゴールマーカーを板上面 world (0,0.9,0.328) に追加.
- スライダを板上 base (0,0.4)=world (0,0.5,0.342) に配置. slider×work_surface 接触ペア + グリッパ×work_surface exclude を追加.

### 鉛直 pusher 化

- 目標姿勢 (ユーザ指定): tool0 +x = base +x, tool0 +z = base −z (鉛直真下) → R_des = [[1,0,0],[0,−1,0],[0,0,−1]].
- 6-DOF 姿勢 IK で厳密達成 (pos 0mm, ori 0°). 60 解中, 重力下垂 0mm の解を採用. 指開閉軸 (gripper +Y) = world +x で押し方向に直交 → 対称接触.
- `run_stage1.py`: `get_jacobian6` / `orientation_error` を追加し, approach (`move_tip_to`) と MPC 押しループに tool0 鉛直保持 (角速度項) を追加. **MPC (Hogan) 本体は不変** (実行層 IK への追加のみ).

### 結果 (`results/20260604_055553`)

- base (0,0.4)→(0,0.8) = world y 0.5→0.9 の 2D 押し成功. 目標到達 (y=0.9002).
- tool0 鉛直保持: 傾き 0.00→0.03°. tip z 0.341–0.342 (安定). 接触維持 (body 内 px 0.004–0.022, 面 ±0.04 内). 以前の接触喪失・アーム暴走・机貫通は解消.
- 残: x ドリフト −0.071m, θ +13.7° (序盤に発生し MPC が戻せず). 主因は MPC 接触点 (gripper_pinch 中心線) と実接触点 (閉じた指前面) の不整合.
- 到達性: グリッパ pinch は z=0.342 で world y=1.0 (base 0.9) まで IK 到達可能と確認. リーチ壁ではなく終端の準特異 + 接触モデル不整合が要因.

## 2026-06-04: 残ドリフトの真因究明と解消

`results/20260604_055553` の残ドリフト (x −70.8mm, θ +13.65°) を ISSUES の仮説 (接触点の法線方向ずれ) を疑って実測検証した結果, **仮説は誤り**と判明し別の真因を特定した.

### 実測 1: 幾何とデータ

- keyframe 姿勢で gripper_pinch は world y=0.469, パッド前面は y=0.480 → pinch はパッド前面より **11mm 後方** (法線方向). しかし MPC ループは `py_body` を常に −0.03 (スライダ面) に上書きしており, 法線方向の食い違いは MPC 入力に届いていない.
- データ 1 ステップ目でスライダが既に y=0.5→**0.611** (+11cm), θ=−2.02° に移動. settle/approach 段階で大きく乱されていた.

### 実測 2: MPC 単体プローブ (決定的)

MPC に θ を与えて出力を観察:
- θ=0: vn=0.08, vt=+0.006 (正常に押す)
- **θ=+13.7°: vn=0, vt=0 (collapse, 押すのをやめる)**
- θ=−13.7°: vn=0.08, vt=−0.018 (正常に補正)

符号非対称が核心. さらに `px_body` を振ると:
- **px_body=+0.004: θ=5°以上で collapse (Q 重みに依らず)**
- **px_body=0.000: θ=13.7° でも vn=0.08, vt=+0.012 と押して θ 補正**

### 真因

1. **接線接触座標 px_body の汚染**: `pusher_in_slider_body` が pinch (接触面から法線方向に ~40mm 後方) で px を測るため, スライダ回転時に `sin(θ)·スタンドオフ (−0.04)` が接線成分へ漏れる. この見かけの偏心 px_body≈+0.004〜0.022 が, モデル上 straight push に +θ トルク (`theta_dot ∝ +px_body·vn`) を生み, 「傾いた状態で押すと θ がさらに悪化」と誤予測させ QP を u=0 に collapse させる. 一方 `run_stage1` は `vn=max(vn,push_speed)` で床上げするため, MPC が止めても斜めに押し続け傾きが固定される.
2. **keyframe 事前貫入**: keyframe でパッド前面 (0.480) がスライダ面 (0.470) を 10mm 貫入. 2s settle がスライダを 11cm ラムして接触を切り, 後の押しで斜めに再接触し θ をスパイクさせていた.

### 対処 (いずれも surgical)

- `run_stage1.py`: MPC に渡す接触点を意図通りの中心対称 `pusher_body=[0.0, −0.03]` に固定 (グリッパは x 対称で中心押し狙い. 横ドリフトは依然 slider-x 状態 vs target で補正される).
- `stage1_scene.xml`: keyframe arm qpos を再計算し pinch を world 0.469→**0.452** に後退 (パッド前面 0.463, スライダ面 0.470 に対し 7mm クリア). 純運動学 IK (`run_stage1` の `get_jacobian6`/`orientation_error` を流用, 物理ステップ無しでスライダ非干渉) で tool-down 姿勢を厳密維持して算出.

### 結果 (`results/20260604_065644`)

- settle 後もスライダは [0, 0.5, 0.342] に静止 (ラム消滅, 仕様の base 0.4 開始を保持).
- **最終: x=−1.5mm, y=0.9015, θ=−0.01°** (ベースライン x −70.8mm, θ 13.65° から). 中間 t=5.09s でも θ=−0.02° の直進.
- ISSUES の該当エントリ削除. 2x2 グリッド動画を出力.
