## Stage 1+ 完了時点の知見

- Stage 0 (解析) と Stage 1 (MuJoCo) の Δθ 傾向は高相関 (r=0.998), 定量的には MuJoCo が ~69% の回転量
- CoM A/B/C 対照は MuJoCo でも成立 (A > B ≈ C). MPC フィードバックが差を縮小する
- elliptic cone が準静的プッシュに必須. 摩擦・接触パラメータの感度は低い
- 準静的仮定の実用的上限は ~0.20 m/s. 0.35 m/s 以上で明確に破綻
- 非一様圧力分布: 押し方向と直交する CoM シフトが支配的. c 補正のみでは不十分

## Stage 2: Robotiq 2F-85 グリッパ統合 (進行中)

当初の横向きグリッパ (指先・フォロワーメッシュ接触) は非対称接触で x ドリフト・回転が大きく不安定だったため, 設計を改訂 (2026-06-04):

- **base フレームを world 整列に再定義** (quat 180°→単位). base +y = 押し方向となり座標系の符号混乱を解消
- **作業板 (work surface)** をテーブル上に追加し, スライダを板上で押す構成に
- **tool0 鉛直下向きの vertical pusher** 化 (6-DOF 姿勢 IK + 実行層の姿勢保持). 閉じた 2 指の対称面を押し方向に直交させ接触を対称化. MPC (Hogan) 本体は不変
- 結果: base (0,0.4)→(0,0.8) の 2D 押しが安定成功 (接触維持・姿勢保持・暴走なし)
- 残ドリフト解消 (2026-06-04): x −1.5mm, θ −0.01° のほぼ直進押しを達成. 真因は接線接触座標の汚染 (px_body に法線スタンドオフが漏れる) による MPC の collapse と, keyframe 事前貫入による settle ラム. それぞれ px_body=0 供給と keyframe 後退で対処

残課題:
- `compute_keyframe.py` を tool-down 6-DOF 生成に同期する (現状の retract keyframe はインライン IK で生成)
